# 02｜合作伙伴重点测试清单

请优先使用一项你真的需要完成的工作汇报，而不是只输入“测试测试”。

## A. 安装与原生 Harness

- [ ] 插件能在官方 DSH `0.1.1-rc.2` Web Profile 安装。
- [ ] Harness 原生侧栏、对话、输入框、权限和模型控件仍可使用。
- [ ] 插件不打开时不会占满页面。
- [ ] 点击标题栏入口后才出现右侧工作面板。
- [ ] 关闭按钮、返回按钮、工作/资产/学习导航容易理解。
- [ ] 简体中文自然；切换 English 后核心页面可独立使用。

## B. 第一步：告诉我想做什么

- [ ] 不看说明也知道输入框要填什么。
- [ ] 示例能帮助下笔，但不会被误认为标准答案。
- [ ] 输入足够完整时，系统不多问，直接制作。
- [ ] 只输入“帮我做一个汇报”时，最多集中问 3 个问题。
- [ ] 澄清问题有推荐答案，并可点击“按建议继续”。
- [ ] 生成期间有明确状态，按钮不能重复点击。

推荐测试简报：

```text
做一份给部门主管的 7 页项目汇报。重点说明项目进度、时间与资源投入、已完成工作和当前困难，希望争取技术支持与资源倾斜。已有材料包括项目进度表、时间记录、成果截图和当前阻塞。最好可以直接发送，合格版本只需微调，三轮修改仍不能使用就算失败。
```

## C. 第二步：检查真实初稿

- [ ] 页面显示约 7 页预览，而不是学习路线或“提交证据”。
- [ ] 有一句核心论点，每页有明确目的和要点。
- [ ] 未提供的数据使用“待补充”，没有虚构业务事实。
- [ ] “查看 AI 假设”容易找到但不喧宾夺主。
- [ ] “下载可编辑 PPT”显示成功状态。
- [ ] PPTX 能在 PowerPoint/WPS 中打开、编辑、另存。
- [ ] Markdown 大纲也能下载并正确显示中文。

请给初稿分级：

- A：可直接发送；
- B：只需微调；
- C：需要明显修改；
- D：基本需要重做。

## D. 第三步：集中修改或确认

- [ ] 一次可以提交一批修改意见，不需要逐题来回。
- [ ] 生成新版时不能重复提交。
- [ ] v2 内容确实根据反馈变化。
- [ ] v1 文件和历史记录仍存在，没有被覆盖。
- [ ] 下载提示不会残留成上一版本的文件名。
- [ ] 最多三轮内能否达到 A 或 B？
- [ ] “接受这一版”含义明确。

## E. 自动沉淀与可选学习

- [ ] 接受终稿后自动生成偏好和交付检查清单。
- [ ] 这些偏好确实来自你的修改，而不是泛泛而谈。
- [ ] “把这个问题学透”只在工作完成后出现。
- [ ] 点击“先结束，保留成果”不会丢失任何文件或资产。
- [ ] 不选择学习，项目仍被标记为完成。

## F. 重启、卸载与恢复

- [ ] 关闭抽屉再打开，当前项目仍在。
- [ ] 刷新浏览器后项目恢复。
- [ ] 重启 DSH 后项目恢复。
- [ ] 卸载后原生 Harness 恢复，用户工件仍在。
- [ ] 重新安装后项目重新出现。

## G. 记录时间和返工

请记录：

- 从提交需求到看到 v1：____ 分钟；
- 从 v1 到接受终稿：____ 分钟；
- 修改轮数：____ 轮；
- 初稿等级：A / B / C / D；
- 终稿等级：A / B / C / D；
- 是否遇到卡死、重复提交或连接重试：是 / 否。
